# 心灵港湾产品设计文档

版本 1.1 · 2026 年 11 月 14 日

本文件描述产品完成后的样子，供项目成员阅读、Agent 直接实现和最终验收。页面、交互、业务规则和默认值共同组成完整交付范围，本文件为实现与验收的统一依据。

## 1. 产品概览

心灵港湾是一款面向高校学生的心理支持 App。学生可以和一个由自己定制外观的 AI 伙伴聊天，在社区表达感受，也可以预约校内心理老师或朋辈获得人工支持。老师和朋辈可在同一个 App 的工作模式或 Web 工作台接待学生、处理回访和跟进。运营人员通过 Web 管理人员、内容和服务。

学生、老师和运营看到的是同一套真实业务数据。一次预约从学生提交到老师确认，一份回访从学生回答到老师处理，都有可见的状态和结果。

### 已确定的约束

- 一所学校使用完整产品，学校名称和服务信息可配置。
- 产品代码统一放在 `oines/xlgw-mono`。
- 同一个 Flutter App 支持学生模式与工作人员模式，Web 工作台使用 React 和 TypeScript。
- 后端使用 Go、PostgreSQL 和 Astral Core。PG adapter 放在 Host，Astral Core 使用外部固定版本依赖。
- 交付真实的助手 3D 形象、捏脸、换装和动作。
- 用户、帖子、聊天、预约和统计来自实际注册与操作。首次安装为空业务库。
- 初始内容只有产品需要的角色资源、情绪标签、问卷模板和默认配置。

下文的账号密码登录、页面结构、资源数量、额度和预约规则，是本次产品设计选定的默认值。文中标为可配置的设置可以在后台调整。

## 2. 角色与整体体验

| 角色 | 日常任务 | 能查看的内容 |
| --- | --- | --- |
| 学生 | AI 聊天、定制助手、社区交流、预约、人工交流、回访 | 本人私有记录和公开社区内容 |
| 心理老师 | 发布时段、确认预约、接待、处理回访和人工求助 | 自己负责的服务，以及学生明确分享的内容 |
| 朋辈 | 提供同伴支持、管理本人预约、必要时转交老师 | 自己负责的服务和普通回访 |
| 运营管理员 | 管理成员与人员、安排服务、处理举报、配置模型与额度 | 业务状态、运行数据、举报证据及完成管理所需的资料 |

这里的朋辈是经学校认可、提供同伴支持的学生志愿者，主要负责倾听、陪伴和分享校园生活经验。学生界面显示“朋辈同学”，并说明“同学倾听与支持”。每位朋辈绑定指导老师，需要老师接手的事项有明确转交对象。

一个账号可以具有多个已授权身份。学生模式和工作模式使用同一个 App，顶部身份入口或“我的”里可以切换。个人 AI 聊天、同学私聊与工作人员的服务记录按身份分别呈现。账号只有工作身份时，首次登录进入工作模式；兼有学生与工作身份时，首次进入选择默认空间，之后记住上次选择。

学生的典型流程是登录后开始 AI 对话，按需要进入校内支持选择人员和时间。预约确认后双方获得服务会话。服务完成后发出回访，学生可以表示希望继续联系，负责人员收到待办并处理。

社区和同学私聊供日常交流使用。工作人员的接待通过服务会话开展，相关预约、参与人和结果始终可查。

## 3. 信息架构与视觉方向

### App 学生模式

底部四个入口为“陪伴、社区、消息、我的”。陪伴页直接提供 AI 聊天。助手旁的“形象”按钮进入编辑器，顶部“找人聊聊”进入校内支持，历史按钮打开已有会话。

| 页面 | 核心内容 | 主要动作 |
| --- | --- | --- |
| 陪伴 | 助手、AI 消息、输入区 | 发送、停止、历史、新对话、找人聊聊 |
| 助手形象 | 3D 预览与外观选项 | 捏脸、换装、预览动作、保存 |
| 校内支持 | 人员、服务方式和可约时间 | 筛选、查看详情、预约 |
| 社区 | 帖子、情绪标签、排序 | 浏览、发布、共鸣、评论 |
| 消息 | 服务会话、同学私聊、通知 | 继续交流、接受私聊申请、查看业务结果 |
| 我的 | 资料、学校、预约、回访、本人内容和设置 | 管理账号、查进度、查看分享、调整偏好 |

一级页面保留滚动位置和输入草稿。详情返回恢复原位置。通知可直接进入对应预约、帖子或问卷。底部红点只表达真实未读，数量以服务端状态为准。

### App 工作模式

老师和朋辈的底部导航为“工作台、预约、消息、我的”。使用同一套视觉系统，顶部始终显示“心理老师”或“朋辈支持”的身份说明。切换身份按钮只列出服务端已授权的身份。

| 工作入口 | 手机上的能力 |
| --- | --- |
| 工作台 | 查看今日安排、待确认申请、待阅回访、待联系和转交事项 |
| 预约 | 按日查看安排，发布或取消空闲时段，确认、拒绝、取消预约，开始、结束服务和标记未到场 |
| 消息 | 查看负责的服务会话与工作通知，回复学生，打开关联预约 |
| 我的 | 编辑接待介绍和服务方式，查看指导老师，管理偏好，切换已授权身份 |

老师在 App 内可以完成认领求助、记录联系、处理回访和结案。朋辈可以接待本人服务、查看普通回访，并向指导老师转交事项。后台的模型配置、人员授权和全校运营仍在 Web 完成。

学生与工作人员的消息、未读和草稿按空间保存。打开工作通知时进入对应的工作身份和记录，返回个人空间仍能找到原草稿。权限撤销后立即更新可选身份并终止相应内容访问。App 与 Web 操作同一业务记录，多端变化后刷新状态，过期操作提示记录已经更新。

### 成品视觉目标

心灵港湾的品牌辨识来自三件可见的东西。陪伴页有细致、有自然表情的 3D 人物，阅读界面以清晰的中文排版和宽松节奏呈现，服务页面用深青绿强调下一步操作。进入任何页面，用户首先看见当前内容或任务，其次看见下一步能做什么，辅助信息退到最后。

App 呈现温暖、平静的校园生活气质。角色拥有完整的发型、面部体积、服装材质与光照。背景以大面积暖灰白和白色形成层次，信息区使用统一对齐与分隔组织。品牌色集中在主操作和选中状态。每个页面只有一个占据视觉主位的实心操作，次要动作通过描边或文字表达。

“完成品”同时要求密集内容、空数据、长文字、键盘展开、网络失败和深色模式都保持完整构图。界面中的人物、人员头像、部件缩略图、图标和文字，必须具有一致的完成度。

### 统一设计系统

以下手机尺寸为 Flutter 逻辑像素，Web 为 CSS 像素，安全区另计。尺寸是正常字号下的基准，文字放大时内容区自然增高。

| --- | --- | --- |
| canvas | `#F5F6F3` | 页面底色 |
| surface | `#FFFFFF` | 表单、列表和浮层内容 |
| surfaceSubtle | `#EFF2ED` | 次级区、输入底色 |
| textPrimary | `#202A27` | 标题、正文、重要数字 |
| textSecondary | `#61706A` | 标签、时间、说明 |
| brand | `#28665C` | 主按钮、链接、选中图标 |
| brandPressed | `#1F5149` | 主按钮按压态 |
| brandSoft | `#E8F0EB` | 用户消息、选中项背景 |
| separator | `#E2E7E2` | 内容分隔 |
| controlBorder | `#7C8981` | 需要明确边界的输入与选项 |
| danger | `#B84943` | 错误和破坏性操作，与文字同时出现 |
| warning | `#795A25` | 待注意的状态文字 |

App 默认跟随系统主题，设置中提供浅色、深色和跟随系统。深色对应 canvas `#171F1C`、surface `#202B26`、surfaceSubtle `#26352D`、textPrimary `#EAF0EB`、textSecondary `#AFBBB3`、brand `#A3D3BE`、brandPressed `#B9E1CE`、brandSoft `#293E34`、separator `#34443B`、controlBorder `#7F9587`、danger `#F2ABA4`、warning `#E4C58D`。深色主按钮文字用深色 canvas。角色有匹配的深色背景与补光，肤色仍然清楚。Web 工作台默认浅色，沿用同一语义层级。

| 文字样式 | 手机字号／行高／字重 | 使用位置 |
| --- | --- | --- |
| 欢迎标题 | 28／36／600 | 空会话的一句欢迎语 |
| 页面标题 | 24／32／600 | 社区、消息、我的、独立业务页 |
| 导航标题 | 18／26／600 | 聊天顶栏、详情顶栏 |
| 内容小标题 | 18／26／600 | 人员介绍、表单分组 |
| 正文 | 16／26／400 | 聊天、帖子、服务说明 |
| 操作与说明 | 14／22／500 或 400 | 按钮、表单标签和次级内容 |
| 元信息 | 12／18／400 | 时间、短状态和辅助计数 |

中文使用系统苹方或 Noto Sans CJK，西文使用 Inter，同一层级跨页面一致。正文按自然中文宽度排版，使用左对齐和明确段距。页面字号体现主次，普通段落每段间距 12，消息组间距 24。业务数字使用等宽数字，状态和姓名使用正常文字。

间距统一为 4、8、12、16、20、24、32、40。手机页面左右留白 20，列表内容与顶栏标题共用对齐线。元素内部优先用 8 或 12，内容分组用 24，主要区块用 32。圆角统一为控件 12、内容面板 16、输入容器 20、底部面板顶部 24。圆形仅用于头像、圆形图标按钮和颜色选项。

基础页面平铺内容。人员列表、消息列表和社区信息流靠对齐与细分隔组织，独立预约结果或业务操作卡片才使用面板。阴影主要用于浮层和悬浮控件，基准为 `0 8 24 rgba(20,35,28,0.08)`。描边与阴影在同一类组件中保持一致。

图标统一使用 Material Symbols Rounded 的 24 网格与一致线条，选中时采用相同图标的实心或加重状态。图标按钮具有 44×44 热区，主要按钮高 48。图标与文字基线对齐，操作区始终有明确的可点击反馈。

| 组件 | 视觉与交互规格 |
| --- | --- |

状态映射固定为待确认、待处理使用 warning 配时钟图标，已确认、进行中使用 brand 配进度图标，已完成、已结案使用次级文字配勾选，已取消、已过期、已拒绝使用次级文字并提供原因。请求失败、输入错误和明确的破坏性操作使用 danger。状态文字始终完整，重要错误另有可执行的处理入口。

数据为空时使用真实的界面结构、一句说明和一个行动入口。角色可以用于陪伴页或账号欢迎画面，普通业务空状态保持简洁。实际头像缺省时使用统一的姓名首字头像，配色从有限中性色组分配。

### 页面空间和响应规则

手机以 390×844 为标准构图，检查 360、390、430 三种宽度。系统状态栏和底部安全区由布局读取。内容不足一屏时保持合理留白，长内容自然滚动。正文、表单、底部按钮和角色都要适应两倍文字尺寸。

顶栏内容高 56。底部导航仅出现在四个一级页，业务详情与形象编辑使用返回导航。键盘出现时陪伴页隐藏底部导航，输入区贴合键盘，收起键盘后恢复。固定底部操作区为内容预留同等滚动空间。

普通反馈用 160–200ms，页面或视图变化用 240–280ms。位移动画先快后缓，返回时复用空间方向。按钮加载、表单反馈和导航状态即时可见，角色动画有独立节奏。

普通文本与其背景的对比度目标为至少 4.5∶1，大字号文字至少 3∶1。手机采用至少 44×44 点击热区，并验证文字放大至 200% 时内容和功能仍可访问。参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)和[文字缩放说明](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。

## 4. 账号、入校与初次使用

### 标准屏构图

登录页在安全区内从上到下展示 48 高品牌区、带学校名的简短介绍、账号密码表单及主按钮。表单最大宽度 360，横向居中，手机两侧至少 24。Logo、标题和输入区共用左侧基线，标题 28／36，介绍 14／22。两项输入间隔 20，主按钮距最后一个输入 24。

注册与登录在同一布局体系中切换。辅助链接位于主按钮下方，协议入口位于内容末尾。键盘出现时允许整体滚动，当前输入和提交入口均可到达。学校名称较长时自然换行。

使用账号密码登录。学生注册填写账号、密码、社区昵称，成功后进入当前学校。账号 4–32 位，密码 8–64 位，昵称 2–20 字。账号唯一，密码使用加盐哈希保存。校方可选择开放注册或要求入校邀请码，默认开放注册，学校固定为后台配置的一所。

老师、朋辈由管理员创建账号或给已有账号授权，授权界面同时填写人员展示资料与服务资格。管理员通过一次性初始化页面建立，初始化完成后关闭该入口。密码可由本人在设置中修改，忘记密码可向运营申请重置，运营生成一次性重置凭证。

学生首次进入个人空间使用默认助手，可以直接聊天。对话偏好里的称呼、年龄段和关注话题均选填。首次使用 AI 时，简短说明消息会发给模型服务、历史保存在账号下，以及工作人员查看资料的范围，用户确认后启用。

退出登录清理本机私有缓存。重新登录恢复本人资料、助手和会话。账号停用后显示状态及联系学校入口，工作人员的未完成服务进入运营的重新分配列表。

## 5. 陪伴与 AI 聊天

### 页面与阅读体验

陪伴页分为空会话、持续聊天和角色展开三种构图，转换沿同一条空间路径进行。

**空会话。** 顶栏高 56，左侧为 44 热区的历史按钮，中央为助手名称，右侧为“找人聊聊”。两侧操作各自占固定空间，中间标题可省略。角色位于主体中央，预览高为可用内容高度的约 35%，上限 280，下限随短屏收缩。人物下方依次为 28／36 欢迎语、两条简短的起聊建议和可输入区域。建议使用轻量选项样式，每条独立一行，点击后填入输入框。助手旁有明确的“形象”操作。

**持续聊天。** 首条消息发出后，原角色区域平滑收为顶栏中央 40 高的头像和名称，消息正文自然填充剩余空间。点击这个头像展开角色预览，编辑通过预览里的“形象”按钮进入。展开后的角色图像可响应轻点动作，图像反馈与编辑导航各有明确入口。

正文左右留白 20，AI 消息最大宽度为内容区宽度，使用 16／26 正文和 12 段距。学生消息右对齐，最大宽度为内容区的 82%，内边距 12×16，浅 brand 背景、16 圆角。消息组间隔 24，连续同方消息间隔 8。时间在间隔超过五分钟或日期变化时出现，使用居中元信息样式。

AI 回复下方的复制和评价操作以低强调度图标呈现，每个有 44 热区，回复完成后出现。模型查询到的人员或时段以独立服务卡片显示，卡片有清楚的人员、时间和动作，卡片左右边界与 AI 正文一致。

**输入区。** 左右外边距 12，下边距 8，加系统安全区或导航占位。输入容器最小高 56、正常字号下最大高 128，圆角 20，文本 16／24。右侧发送或停止按钮热区 44，正常字号最多显示四行后内部滚动。大字体时按实际行高减少可见行数，并保证至少一整行可见，空间不足时内容内部滚动。键盘出现时收起展开角色并隐藏底部导航，输入区贴合键盘上沿。

新消息到达时，用户位于底部才跟随滚动。向上阅读后出现“回到最新”浮动小按钮，位于输入区上方 12，位置固定。切换标签或暂时离开保留草稿。回复失败的提示和重试属于失败的那一轮，排在该消息下方，已显示的历史保持稳定。

### 功能与规则

- 每个会话有标题、历史和归属账号。支持新建、按标题搜索、重命名与删除。
- 单条输入最多 4,000 字，去除首尾空白后不能为空。输入框支持换行，并随内容适当增高。
- 一个账号同一时间生成一条 AI 回复。生成时“发送”变为“停止”，用户可以继续编辑下一条草稿。
- 回复支持复制、标记有帮助或需要改进，后者可附文字意见。
- 标题由首条内容生成，失败时使用“新对话”。标题生成与聊天互不阻塞。
- 对话历史保存在服务端，同账号换设备可以继续使用。
- 点击“结束本次聊天”返回新的空会话，已有会话留在历史，可再次打开续聊。

| 状态 | 用户看到什么 | 行为 |
| --- | --- | --- |
| 发送中 | 用户消息旁显示发送中 | 接收成功后解除发送状态 |
| 等待回复 | “正在整理回复”及轻微等待动作 | 可停止 |
| 回复中 | 文本逐步出现 | 可停止、阅读历史 |
| 已完成 | 回复操作出现 | 可继续发送 |
| 已停止 | “已停止生成” | 原输入保留，可选择重新生成 |
| 失败 | “这次回复没有完成”及重试 | 重试关联原输入，用户消息仍只有一条 |
| 网络中断 | “正在重新连接” | 重新读取本轮状态和历史，恢复展示 |

每次发送具有稳定标识。连点、重连和网络重试不会重复创建用户消息。临时回复按会话和运行标识展示，切换会话不会串内容。用户停止后以服务端确认状态为准，已经完成的回复正常显示。未完成片段带标识，不能被当作已完成历史继续传给模型。

### AI 与业务的连接

AI 可以通过工具查询本校人员、时段、学校服务信息和本人预约，结果使用真实对象生成可点击卡片。需要创建预约、分享资料或请求人工联系时，先打开明确的业务确认界面，再由用户提交。

模型请求统一经过后端模型网关。App 只保存用户登录凭证，模型供应商密钥由服务端管理。模型未配置或暂不可用时给出明确反馈，并保留校内支持、社区和已有历史入口。

## 6. 助手捏脸与动作

### 外观规格

角色的完成度按近景人物资源检查。采用自然青年比例的风格化 3D，参考全身比例约 1∶5.5，肩颈和面部结构连贯。鼻翼、唇缘、眼睑、下颌具有清楚体积，眼球包含可辨的巩膜、虹膜和柔和高光。三种预设通过轮廓、发型与服装形成辨识度，细节精度一致。

皮肤为非金属哑光材质，面颊与鼻部有细微暖色变化。头发具有大轮廓、发束和局部细节，耳侧、后脑和鬓角完整。衣服展示领口厚度、主要缝线和少量结构褶皱。材质粗糙度和光照一起调校，使所有肤色下的五官都能看清。

镜头采用约 55mm 等效的透视效果，默认胸像，双眼位于预览上方约 42%。人物面向用户，镜头保持自然透视。前上方约 45° 柔和主光配约三分之一强度的辅光，微弱轮廓光帮助分离头发和背景。背景为平静的暖灰色面，人物周围保留动作和旋转空间。

定制对象是 AI 助手。采用统一风格的半身 3D 青年角色，轮廓柔和、材质干净，五官在手机上清楚可辨。完整资源包含三个人物预设、六款发型、三款上衣及配色、十项捏脸参数、骨骼与基础动作。

三个预设分别为清爽短发、柔和中发、利落长发，默认使用清爽短发。预设使用同一套可调模型，用户选定后仍能继续编辑。

| 分类 | 可调整内容 |
| --- | --- |
| 脸型 | 脸宽、脸长、下颌宽、下巴长度 |
| 五官 | 眼睛大小、眼距、眉毛高度、鼻宽、鼻长、嘴宽 |
| 发型 | 六款可视缩略图 |
| 配色 | 六款肤色、八款发色、六款瞳色 |
| 穿搭 | 圆领衫、衬衫、卫衣，每款三种配色 |

十项捏脸参数显示为 0–100，默认 50。合法范围映射到真实模型形变，五官变化要在正面和侧面都能看见。人物部件、骨骼动作与外观参数共同作用时，避免明显穿模。

### 编辑页面

编辑器使用独立全屏，顶部 56 高操作栏固定取消、标题和保存。取消与保存的热区均至少 44，保存是该页面唯一的主要操作。默认预览区占操作栏以下可用高度约 44%，其余空间给编辑面板。短屏优先压缩预览，确保至少两行选项或两组滑杆可见。

预览右下放回正按钮，左下放动作预览，两者与人物分离。手势支持水平旋转、双指缩放。五官编辑时以约 250ms 平滑靠近脸部，穿搭页回到半身，切换过程保留当前草稿。

下方编辑面板使用 surface，顶部圆角 24。分类栏高 48，按原始顺序横向滚动，选中项使用 brand 字色和短下划线。预设以三列显示完整人物缩略图；发型和服装使用同角度、同光照、同裁切的实际模型缩略图，三列间距 8。每项包含清楚名称，选中有 2 像素边框与勾选。

滑杆行包含名称、当前数值和轨道，轨道下方留出 44 高触摸范围。每行占高至少 72，滑杆最大化占用宽度。色块点击区至少 44，按网格排列，选中有双层轮廓，色名可读。面板内容独立滚动，顶部预览与保存仍然可见。

调整实时生效于草稿。选择预设替换整套草稿，可撤销本次替换。保存成功后应用到该账号所有 AI 会话里的助手展示。保存失败保留修改。取消或系统返回遇到未保存修改时，询问放弃或继续编辑。“恢复预设”也只作用于草稿，需保存才正式生效。

模型文件和配置带资源版本。用户保存后重新登录能恢复相同外观。两个设备同时编辑时，保存冲突提示重新加载或明确覆盖。

### 动作设计

| 情境 | 动作 |
| --- | --- |
| 进入陪伴页 | 短招手或点头，十分钟内最多播放一次 |
| 待机 | 轻微呼吸与自然眨眼 |
| 输入中 | 保持注视，使用平缓的倾听姿态 |
| 等待模型 | 轻微侧头或思考姿态 |
| 回复出现 | 小幅点头或手势，每条回复最多一次附加动作 |
| 点击角色 | 待机时短点头回应，连续点击合并处理 |
| 结束本次聊天 | 简短挥手 |
| 求助面板出现 | 中性静止姿态 |

待机呼吸保持约 0.5%–1% 的可见起伏，眨眼间隔在 3–7 秒内变化。头部微动通常不超过 3°，点头约 5°，挥手约 1.2 秒。角色动作以自然加减速进入与退出，动作之间使用 150–250ms 过渡。捏脸后的眼睑闭合、嘴角连续性和眼球位置必须与动作一起检查。以上参数作为动作调校基准。

优先级为后台暂停、减少动态或静止模式、求助面板、等待与回复、点击回应、待机。文字交流时嘴部自然闭合。动作结束平滑回到当前状态，避免突然跳姿态。

设置提供标准、轻微、静止三个动作选项。系统开启减少动态时使用静态姿态。离开页面或进入后台暂停渲染，恢复时读取当前状态。角色加载失败展示缓存静态形象，聊天继续可用。

Blender 源文件、生成脚本、GLB 和动画一并保存。使用 Flutter 控件与 Three.js 视口组合呈现，目标手机交互至少稳定 30 FPS。需要检查三视角、参数极值、换装与动画组合的实际视觉效果。

## 7. 校内支持、预约与人工交流

### 人员与预约的标准构图

校内支持页以页面标题、两类人员切换、日期与方式筛选、人员列表顺序排布。筛选区高至少 44，选中条件可一键清除。人员项采用通栏排版，左右 20 留白、上下 20，头像 56，姓名 17／24，身份 13／20，简介最多两行。最近可约时间单独成行，与姓名、简介形成三级层次，整项可点。

人员详情顶栏下先展示头像与姓名，再是服务介绍、方式与地点、日期选择及可约时段。头像为真实人员上传资料或统一姓名头像。日期横向滚动，每格宽 48、高 64、间距 8，选中态有明显底色和文字状态。时间三列排列，格高至少 44、间距 8，可用、已选、不可用有清楚区别。

底部固定选择摘要与确认按钮，内容区高至少 80 加安全区，上方内容预留相同空间。未选择时显示“请选择时间”，按钮禁用。选中后显示完整日期、星期、时间和服务方式。确认页在一屏可见人员、时间、方式、地点和提交动作，补充说明位于其后。提交成功进入预约详情。

预约详情的视觉焦点是状态、时间和人员。顶部使用一个清楚的状态标题，下方时间采用 24／32，人员与地点使用正文层级。过程记录垂直排列，已完成步骤与当前步骤有文字说明。底部只展示当前状态允许的主要动作，取消等低频操作放在明确可发现的位置。

### 人员列表与详情

校内支持页按心理老师、朋辈切换，支持服务方式与日期筛选。列表展示头像、姓名、身份、简介摘要、可用方式和最近时段。详情展示服务介绍、地点或线上方式、日历和预约按钮。

人员资料来自后台维护。没有评价数据时不展示评分，没有可约时间时显示“近期暂无可约时间”并提供换日期或查看其他人员的操作。

### 预约规则

服务默认免费。老师每次 50 分钟，朋辈每次 30 分钟，相邻时段间隔十分钟。工作人员发布未来十四天的时间。学生选择人员和时段，选填最多 500 字的说明，确认后提交。

提交时服务端验证时段仍可用，并锁定占用。工作人员确认或拒绝，双方收到通知。学生最多有三个未结束预约。学生和工作人员的时间都不能与已有有效预约重叠。

| 状态 | 允许的操作 |
| --- | --- |
| 待确认 | 工作人员确认或拒绝，学生取消 |
| 已确认 | 开始前取消，工作人员开始服务 |
| 服务中 | 工作人员结束服务 |
| 已完成 | 查看结果、回访和后续安排 |
| 已拒绝／已取消／已过期／未到场 | 查看原因，重新预约 |

开始时间仍未确认的申请自动过期。取消或拒绝释放时段，工作人员操作需要填写简短原因。改期通过“取消并重新选择时间”完成，界面先告知学生原预约将取消。开始十分钟后工作人员可标记未到场。服务开始后通过结束服务收尾。

确认后建立服务会话，顶部固定显示关联预约。线上咨询在该会话开展，线下咨询也可用于确认地点和安排。服务完成后保留七天补充交流，之后只读。预约取消、过期、拒绝或标记未到场时，已有服务会话立即只读，关联 AI 分享失效。服务消息最多 2,000 字，支持发送状态、复制和失败重试。

工作人员结束服务时填写简要内部记录，可另外填写学生可见的下一步安排。学生可以向运营反馈服务问题并申请更换人员。

### AI 内容分享

预约本身不开放 AI 历史。学生主动选中具体消息或生成并编辑摘要，在确认页看到接收人员、内容和关联预约，再提交分享。分享为只读内容快照，后续新增消息不自动追加。

分享默认在服务完成七天后失效，可提前撤回。接收人查看时检查有效授权。删除原会话或撤回分享后，分享入口失效。工作人员转交服务时，新的接收人需要学生重新确认分享内容。

## 8. 社区、私聊与消息

### 社区

页面标题高 56，排序栏高 44 并吸顶。帖子铺在连续的 surface 内容区，每帖上下留白 20，帖子之间用细分隔。作者头像 36，昵称 15／22，时间 12／18。正文与作者间距 12，正文 16／26，互动栏与正文间距 16。情绪标签使用小型浅底文字，同一行最多三项。

共鸣和评论在底部同一行，图标 20，数字 13，热区至少 44。共鸣选中用 brand 与对应图标状态，计数更新保留布局。更多操作在作者行右侧。发布入口为右下方 52 的悬浮按钮，距导航上沿 16、右侧 20，图标与无障碍名称明确。

帖子详情保持相同正文宽度，作者信息、全文与评论依次排布。评论头像 28，回复层级最多一层缩进 16，长线程通过“查看回复”进入，避免持续压缩正文宽度。评论输入固定在底部。发帖页面以大面积可编辑正文为主，情绪标签紧随正文，发布按钮固定在顶栏右侧，草稿状态轻量呈现。

社区采用可连续阅读的信息流。顶部提供“最新、热门、最多共鸣”，默认最新。帖子显示昵称、头像、发布时间、正文、情绪标签和互动数。卡片正文超过六行折叠，点正文进入详情，点作者进入社区主页。

帖子必须有正文，最多 2,000 字，选择 1–3 个情绪标签。发布页自动保留本机草稿，发布成功清空草稿并回到新帖子。用户可编辑、删除自己的帖子。编辑保留发布时间并标记已编辑。

共鸣为可取消的单次互动，同一用户对同一帖子只有一份有效记录。评论不能为空，最多 500 字，可回复指定评论。本人可删除自己的评论，删除后互动数同步更新。热门按共鸣数加两倍评论数排序，最多共鸣按共鸣数排序。

社区主页展示本人公开帖子，自己的主页还可查看已发评论。用户可举报帖子或评论、屏蔽作者。举报需要选择原因，可补充最多 500 字说明。运营处理后，举报人在消息中收到结果。

帖子被删除或下架后，旧通知打开时显示“内容已不可用”并提供返回社区。屏蔽后的内容从自己的信息流隐藏。

### 同学私聊

从社区作者页发起交流申请，可附一百字说明。双方均须为当前学校有效用户。对方在消息里接受后建立会话，拒绝后结束申请。每对用户只有一个待处理申请，有效期七天，拒绝后七天内不可重复申请。

私聊显示社区昵称，不暴露账号联系方式。支持文本、未读数、失败重试、屏蔽和举报。屏蔽立即阻止新申请和新消息，原记录仍可阅读。同学私聊屏蔽不影响系统通知或预约处理。

用户可以结束交流，结束后的会话只读，再次交流需重新申请。服务会话和同学私聊具有明确标签。

### 消息中心

标题和通知入口位于 56 高顶栏。会话行最小高 80，左右留白 20，头像 48，头像与文字间距 12。名称 16／24，时间 12／18 与名称同排并右对齐。摘要使用 14／22 单行省略，未读数占固定位置。服务身份使用简短文字标识，信息行高度保持统一。

服务聊天顶部增加 56 高预约摘要，点击可查看详情。人工和同学消息气泡最大宽度为内容区 78%，正文 16／24、内边距 12×16，连续同方消息间距 8、换人间距 20。日期分隔使用居中的元信息样式。会话只读时，输入区的位置展示结束原因与可用的后续动作。

默认展示聊天会话，顶部有“通知”入口及未读数。聊天按最近消息时间排序，服务会话展示人员身份，私聊展示社区昵称。通知包含预约结果、回访、人工联系、社区互动和举报结果。

打开会话或通知详情后标记已读。支持全部已读。消息发送中禁用本条重复操作，失败在原消息旁显示重试。通知只展示处理所需的简短信息，点击后查看具体内容。

### 我的页面

顶部显示 64 头像、昵称和学校，头像与学校信息能直接进入编辑。下方先是预约与回访两个清楚的任务入口，有真实待办时显示数量。再按内容与偏好、账号与帮助两组排列普通设置行，每行至少 56，左侧名称、右侧当前值或进入箭头。

伙伴形象一行显示当前助手的真实缩略图，进入同一个形象编辑器。今日 AI 剩余次数以普通信息行呈现，用量接近上限时才增强提示。版本信息位于页面底部的次级文字区。

## 9. 回访与人工求助

### 回访

问卷页面顶栏显示标题，首段用两行以内说明关联服务和填写目的。每个问题单独成组，题目 18／26、说明 14／22，组距 28。选项采用整行单选，高至少 48、间距 8，点击整行可选。自由意见使用三行以上文本域，底部固定提交按钮，保存草稿为次要操作。

必填未完成时，在问题附近给出说明，已填写内容保持原位。提交成功页使用状态图形、明确结果和“返回消息”按钮，后续查看采用相同题序和只读答案样式。需要继续联系的选择与补充意见保持相邻，用户能理解会发生的操作。

工作人员结束服务时，系统立即创建一份关联回访并通知学生。后台可以将发送时间改为延迟，默认即时发送。每次服务只有一份正式回访问卷，重复结束请求复用原问卷。工作人员可以对尚未提交的问卷补发通知，保留发送记录；已提交问卷不再补发。

问卷包含当前状态、帮助程度两个必填单选，推荐意愿与补充意见选填，并提供“希望工作人员继续联系我”。草稿保存到服务器，重新进入继续填写。提交后显示已完成，可再次查看，答案只读。

普通回答交给原服务人员处理。如果学生选择希望联系，或自述状态变差，生成老师跟进待办。老师服务由原老师负责，朋辈服务由指导老师负责。未作答只记录未作答。

工作人员可以标记已阅无需联系，或记录联系过程和后续安排。处理状态为待阅、待联系、跟进中、已结案。学生提交问卷和工作人员结案分别记录。服务人员停用后，未完成待办进入运营重新分配列表。

### 人工求助

求助页面使用标题、学校服务时间、联系信息和说明输入的直接布局，主要按钮为“提交联系请求”。结果页突出当前状态和负责人，跟进记录向下排列。等待处理时显示真实状态，存在下一步操作时用明确按钮提供。

学生从陪伴页或校内支持页点击“希望有人联系我”，填写联系方式、想说明的事情和方便联系的时间，确认后建立求助记录。AI 可以给出这一入口，实际提交由学生确认。

运营将求助分配给老师，老师认领、联系、记录跟进和结案。朋辈服务需要老师接手时走同一转交流程，接收人确认后更新负责人。转交或重新分配时，同步更新对应服务会话的参与者，原人员失去服务内容的读取与发送权限，新人员获得接待所需权限。AI 分享仍由学生向新人员重新授权。学生看到已提交、已分配、联系中和已结束等实际状态。

学校的服务时间和联系信息由后台维护，求助页清楚展示。人工求助、预约和普通 AI 聊天分别保留记录和处理结果。

## 10. 工作台产品设计

### 手机工作区的构图

工作模式采用 56 高顶栏和 64 高底部导航，安全区另计。标题旁显示当前工作身份，可切换身份时有明确下拉箭头。主要视线落在待处理事项，使用与学生端一致的文字、间距和按钮体系。

“工作台”顶部显示今天日期和真实待办数量，下面为待确认、回访、跟进筛选及任务列表。每项以时间、学生昵称、服务类型和当前状态组织，行高至少 88，上下间距 16。点击进入任务详情，主要操作固定在详情底部。空状态给出查看预约或设置可约时间的入口。

“预约”页使用一周日期条与当天安排列表。日历选中状态和日期区样式与学生端一致。右上“排班”进入时间选择，手机可以新增日期和时段、发布、删除尚未被预约的时段。已被预约的时段直接打开预约记录。批量编辑多周安排可在 Web 日历完成。

“消息”沿用 80 高会话行和人工聊天样式，顶部预约摘要可进入详情。工作身份、对方昵称、服务状态均可辨认。“我的”分为接待资料、服务设置和账号三组，朋辈在接待资料中显示指导老师及联系入口。

填写服务记录和处理回访采用独立页面，长文本随键盘滚动，底部主要操作始终可达。内部记录和学生可见安排有不同的字段标签与说明，提交前可以预览发给学生的内容。

### 桌面工作区的构图

工作台以 1440×900 为标准画面。左栏宽 224，顶部栏高 64，主区留白 24。导航名称、选中项与当前页面标题对应。页面标题 24／32，说明 14／22，右侧放本页主要操作。筛选工具条高至少 40，与标题间距 20、表格间距 16。

表头高 44，数据行最小高 56，文字 14／22，单元格横向内边距 16。姓名与正文左对齐，数字右对齐，日期和状态列保持固定宽度。常用行操作直接显示文字入口，更多低频操作进入菜单。分页固定在列表末尾，选中行、悬停行和键盘焦点分别有可见状态。

详情侧栏宽 440，标题、摘要、表单和时间线沿同一条左对齐线排列，底部固定当前允许的主要操作。读长记录、持续聊天和复杂编辑使用独立页面。遮罩层关闭时返回原列表位置与筛选。

服务会话在 1440 及以上采用左侧会话列表 280、中间交流区自适应、右侧资料区 320。1280–1439 时资料区收为可打开的侧栏，保留足够交流宽度。1024–1279 时全局导航折叠为 72，资料继续使用侧栏。窄于 1024 时显示导航抽屉，服务列表和会话按页面切换。长表格只在表格容器内水平滚动，页面标题和操作保持可达。

工作台的首要内容是待办列表。统计页首行最多四个指标，数字 28／36、标签 13／20，各项用量有一致单位。图表显示真实时间范围和坐标，鼠标与键盘可查看明细。无数据的图表显示明确空状态，有数据后维持同一尺寸。

下列功能使用同一套业务操作，右侧栏、三栏会话和周日历均为 Web 布局。手机按本章“手机工作区的构图”呈现，以独立详情页完成相同操作。预约详情两端都根据状态提供取消和标记未到场入口。

### 我的待办

老师和朋辈登录后看到今日预约、待确认申请、回访待阅和待跟进事项。默认按临近时间排序，点击事项进入可操作详情。没有待办时显示“当前没有待处理事项”和排班入口。

### 预约与排班

使用周日历和列表双视图。工作人员可选择日期、起止时间和服务方式批量发布时段。已有预约的时间在日历中直接显示学生与状态。点击预约打开右侧详情，可确认、拒绝、取消、开始或结束服务。

运营可筛选人员、日期和状态，处理无人负责的预约，重新分配时同时校验新人员时间，并通知学生。

### 服务会话与回访

会话页面采用左侧会话列表、中间交流区、右侧服务信息。右侧展示关联预约、当前服务状态和学生授权的资料。内部记录在独立区域编辑，学生可见安排明确标注。

回访页以状态、负责人员和时间筛选。详情展示问题、答案和跟进记录。每次联系记录包含时间、操作者和结果，下一步安排可发给学生。运营看到待办归属与处理进度。

### 成员与服务人员

可搜索账号和昵称，查看账号状态，创建工作人员、授予角色、编辑服务介绍和停用资格。朋辈资料包含指导老师。停用前展示未完成事项，确认后转入待分配队列。

普通运营页面不提供全站私人聊天搜索。阅读举报消息限定于用户提交的证据，阅读服务内容要求对应服务关系和权限。

### 社区管理与应用反馈

举报列表展示对象、原因、提交时间和状态。详情显示被举报内容和必要上下文，运营可以驳回、下架内容或限制账号，并填写给举报人的结果。

应用反馈支持用户在“我的”主动提交问题和建议。列表可筛选待处理、处理中、已解决，运营可回复，学生在通知里收到答复。

### 统计与配置

业务统计展示真实注册人数、活跃人数、AI 使用次数、预约完成数、回访提交数和未处理事项。可按日期筛选，零数据如实显示为空或零。

学校配置包含名称、Logo、介绍、服务地点、联系方式、时间、注册模式和预约回访规则。模型配置与额度在单独页面管理。配置保存成功后明确反馈生效范围。

## 11. 模型网关、限额和限流

模型网关是 Go 后端中的模块。所有模型调用通过它访问供应商，统一处理配置、认证、超时、调用记录和用量。Astral Core 负责 AI 执行与重试，网关每次处理一次真实出站请求。

### 连接和模型

模型管理采用“连接、用途配置、调用记录、额度”四个页面内导航。连接列表展示名称、供应商、启用状态和最近测试结果，密钥以固定长度掩码显示。编辑在侧栏完成，测试结果留在按钮附近，错误原因可展开。用途配置按聊天、摘要、标题逐行展示当前模型，保存后说明对新请求生效。

调用记录用表格显示时间、用户、用途、模型、耗时、用量和结果，失败可按类别筛选。详情保持概要在上、诊断在下，长字段能复制。额度页把全局默认与个人覆盖分组，输入旁直接显示单位，保存结果和当前生效值清楚可见。

运营可以新增、编辑、启停供应商连接，字段包括名称、协议、服务地址、密钥和模型名称。支持当前 Astral 适配的供应商，默认使用 DeepSeek 的 OpenAI 兼容接口。服务端验证连接地址，普通用户无法传入任意地址。

密钥写入后只展示掩码，可替换和测试连接。密钥使用服务端环境密钥加密保存，日志与普通 API 不返回密钥。连接测试发送一条明确的测试请求，显示成功或失败原因，记录这次真实调用。

建立三个用途配置，分别为聊天、摘要和标题。每项选择连接、模型、温度及输出上限，可共用同一模型。新配置作用于新请求，已经开始的请求保留原目标。紧急停用连接会阻止新的供应商请求。

可以设置备用连接。主连接被手动禁用或标记不可用时，新请求选备用连接。已经开始输出的回复保持原运行状态，失败后由用户重试发起新的运行。界面在调用详情中显示实际使用的连接与模型。

### 默认额度

| 控制项 | 默认值 | 作用 |
| --- | --- | --- |
| 单用户每天 AI 消息数 | 40 条 | 按服务器受理的用户输入计数，同账号跨设备共享 |
| 单用户发送频率 | 每分钟 6 条 | 超出返回可重试时间 |
| 单账号在途生成 | 1 条 | 返回正在执行的会话，引导继续或停止 |
| 全局模型并发 | 10 个名额 | 聊天受理时占用，运行结束释放，满时提示服务繁忙 |
| 单次供应商超时 | 45 秒 | 超时交给 Core 按策略处理 |
| 自动尝试次数 | 最多 2 次，含首次 | 网关自身不再叠加重试 |
| 一次逻辑回复总时限 | 90 秒 | 到期由 Host 取消当前执行 |
| 聊天最大输出 | 2,048 token | 模型支持范围内校验 |
| 输入上下文预算 | 默认 16k token，受模型实际窗口约束 | 超预算由 Astral 压缩历史，并为输出预留空间 |

运营可以修改全局默认和某个用户的每日额度、频次与启用状态。每天按学校时区零点重置计数。额度设为零表示禁用 AI 新请求。额度不足、并发满、频率拒绝均发生在受理前，拒绝请求不扣每日次数。

同一输入 ID 的重复提交返回原接收结果，只扣一次额度。供应商自动重试不重复扣用户消息数，实际请求次数和 token 分别记录。全部尝试都失败且没有完整回复时，返还本次占用的日额度，扣还记录幂等处理。用户主动停止保留这次已使用次数。

用户点击“重试”是独立的恢复操作，通过 Host 为原业务输入发起新的运行，仍检查频率、并发和启用状态。原次数已因失败退还时，重新受理扣一次；原次数因主动停止仍保留时，复用该次数。每次扣还都有对应记录，重复操作不会多退。普通网络重复提交不会触发重新生成。Core 自动重试和未完成执行恢复保留冻结目标，已结束运行的主动重试可按当前配置选路。

聊天受理时原子取得一个全局并发名额，本运行内的回复、摘要和自动重试顺序使用该名额，完成或终止后释放。后台标题和连接测试取得同一池中的剩余名额，标题暂未取得时使用“新对话”，连接测试提示繁忙。服务重启清理遗留占用并按持久运行状态恢复。

取消请求时终止本轮执行，已发生的供应商用量正常记录。标题和摘要不消耗用户消息次数，但计入实际调用与 token 用量。供应商没有返回用量时显示“用量未知”，不能显示为零。

### 学生和运营分别看到什么

学生在设置里可查看今日剩余次数。接近用完时轻量提示，不持续占用聊天区域。额度耗尽显示恢复时间，仍可访问历史与其他业务。频率超限显示“发送得有点快，请稍后再试”。全局繁忙、网络问题和模型配置问题使用不同错误状态，失败输入保留。

模型后台提供连接状态、调用总量、成功失败、耗时、输入输出 token、取消次数及额度拒绝记录。调用列表显示时间、用户、用途、模型、结果和错误类别，可以查看单次诊断信息，默认日志只记录定位问题所需的元数据。

后台可选填模型输入与输出单价，用实际 token 计算估算费用。价格未填时只展示 token。费用标为估算，用于项目观察调用成本。管理员可以按全站或个人暂停 AI 使用，配置操作保留记录。

## 12. 通用状态和交互细节

| 情况 | 统一表现 |
| --- | --- |
| 首次加载 | 骨架屏，结构与真实内容接近，避免页面跳动 |
| 空列表 | 一句说明和与当前任务有关的入口，例如“还没有预约，去找人聊聊” |
| 加载失败 | 原位置展示重试，已经加载的内容保留 |
| 表单错误 | 标在具体字段下，保留输入，定位首个错误 |
| 正在提交 | 主按钮显示进度并防重复，成功后显示真实业务结果 |
| 删除 | 展示对象和影响，确认后完成，失败时恢复可操作状态 |
| 数据已变化 | 提示刷新后的状态，保留仍有用的输入 |
| 登录失效 | 引导登录，成功后回到原目标页面 |
| 无访问权限 | 明确说明并提供返回，服务端同样拒绝读取 |
| 长内容 | 正文自然换行，详情能读全，操作区始终可达 |

搜索有清空按钮，筛选有已选状态和重置，列表下拉刷新保留筛选。重复进入页面保持当前上下文。成功反馈优先使用轻量提示，必须由用户决定的操作才使用确认对话框。

按钮、输入、选中、禁用、焦点和错误状态统一。表单有可读标签，输入类型与键盘匹配。关键状态使用文字说明，图标提供无障碍名称。手机适配大字体和减少动态，Web 支持键盘访问与可见焦点。

文案使用直接、平和的语言，例如“预约已提交，等待老师确认”“形象保存成功”“这次回复没有完成，可以重试”。与服务状态有关的文案必须对应后台真实结果。

## 13. 数据和工程约定

### 核心对象

| 对象 | 必要信息 |
| --- | --- |
| 用户与角色 | 账号、密码哈希、昵称、头像、学校、角色、账号状态 |
| 服务人员 | 用户关联、身份、介绍、服务方式、地点、指导老师、启用状态 |
| AI 会话 | 用户、标题、Astral 会话关联、创建和更新时间、运行状态 |
| 助手配置 | 用户、模板与资源版本、十项捏脸参数、颜色、发型、服装、动作设置 |
| 时段与预约 | 人员、学生、开始结束时间、方式、说明、状态、变更记录 |
| 会话与消息 | 类型、参与者、关联预约、正文、发送标识、时间、已读位置 |
| 分享 | 学生、内容快照、接收人、服务关联、有效期、撤回状态 |
| 回访 | 服务、模板、答案、提交状态、负责人、处理记录 |
| 社区 | 帖子、标签、评论及回复、共鸣、举报、屏蔽关系 |
| 求助 | 学生、联系说明、负责人、进度、转交和跟进记录 |
| 模型网关 | 供应商连接、模型用途、额度设置、输入去重、调用与用量记录 |
| 运营 | 通知、应用反馈、学校配置、操作记录 |

Go 是业务鉴权和状态修改入口，PostgreSQL 保存业务记录和 AI 运行状态。用户只能操作自己或被授权的对象，工作人员的角色由服务端判断。预约占位、共鸣去重、消息去重及额度扣还使用事务和唯一约束保证一致。

AI Host 通过公开 Store 接口实现 PG adapter。每个会话同时只有一个运行所有者，持久结果以 Astral 历史与快照为准，订阅只用于实时展示。实际模型调用的两条路径都经过网关，恢复和重试仍遵循额度与连接状态。

App 的模型密钥迁到服务端，私人数据通过认证 API 读取。资源文件放对象存储或可配置本地目录，使用不可变版本，App 缓存已下载的角色。运行数据删除同步处理关联分享，运行日志避免记录完整聊天与密钥。

## 14. 人与 Agent 共用的完成标准

以下是产品整体完成后的检查方式。

1. 从空业务库启动，创建管理员，注册真实学生，授权老师和朋辈，在同一 App 中分别进入个人与工作模式，并可登录 Web 工作台。
2. 学生定制一个可旋转的 3D 助手，调整五官、换装、查看动作，保存后重新登录恢复相同形象。
3. 学生完成多轮真实 AI 对话，历史可查，停止、失败重试、断线恢复和切换会话结果正确。
4. 修改每日额度和频率限制后实际生效，重复提交不重复扣次数，后台显示真实调用和 token。
5. 老师发布时段，学生提交预约，老师确认，双方可以真实交流，另一学生无法读取该服务。
6. 同一时段并发预约只有一份有效占用，取消后时段恢复可选。
7. 完成服务后产生回访，学生提交，工作人员查看、联系并结案，双方状态一致。
8. 朋辈向指导老师转交事项，老师接收后成为负责人。
9. 两个学生真实发帖、评论、共鸣，通知与计数一致，私聊申请被接受后可以互发消息。
10. 举报、屏蔽、下架与账号停用在相应界面真实生效。
11. 分享内容只向指定人员开放，撤回和删除后原分享不可访问。
12. 空库、空列表、资源加载失败、模型错误、无权限和登录失效都有完整界面。
13. 常用手机尺寸、键盘、大字体和 Web 窄窗口下，文字、角色、表单与操作区都可使用。
14. 完整交付 App、工作台、Go 服务、数据库结构、角色源文件和启动说明，所有统计基于实际记录。
15. 老师和朋辈仅使用 App 即可完成本人接待、服务消息、回访及转交，Web 显示相同记录。多身份切换时消息、草稿和权限正确。

页面中的按钮、筛选、提交、设置和状态必须对应实际行为。页面结构与业务规则以本文为准，组件实现可以使用成熟库。视觉效果按本文件的版式、字体、配色、动作和状态规范完成，角色美术与交互应通过实际画面检查。
